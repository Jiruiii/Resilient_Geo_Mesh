# 政府人員登入與官方消息發布實作計畫

## 範圍

依已確認的「政府人員登入與官方消息發布／查證計畫」新增單一試辦機關的政府工作台。系統管理者先核實任職身分，再直接建立政府人員帳號；帳號識別不限定電子郵件，不開放自行註冊。Web 與 Android 共用 API 和 Flutter 畫面；Android 保留離線及 mesh 回報，Web 回報需連線。公告與查證事件由現有中央 Ed25519 金鑰簽署，公開 API 和工作台 API 均不持有私鑰。

## 工作項目

1. PostgreSQL migration、資料存取層、首位系統管理者 bootstrap、管理者建立帳號／登入／停權 API 與稽核。
2. 原始裝置簽章回報上傳、冪等保存、政府待查清單及 `official.verified` 決策佇列。
3. 公告建立、修訂、撤回 API，可靠 outbox worker，並將兩類事件送入現有簽章 feed。
4. Flutter Web／Android 個人頁登入狀態、帳號登入／登出、管理者帳號管理、公告管理及查證工作台。
5. Web 裝置金鑰簽章與線上回報；Android 已簽章事件的連線上傳佇列和重試。
6. Web、Android feed 驗證器允許官方公告及查證來源，既有通知呈現公告及回報查證狀態。
7. Compose 設定與操作文件，說明 bootstrap、直接建立帳號、金鑰隔離、重試和驗收。

## 驗收

- 後端測試只有系統管理者能建立帳號、非電子郵件帳號登入、密碼至少 12 字元且不限制字元種類、停權、登入與登出、回報簽章與期限、重複上傳、payload hash 比對、公告版本／撤回、outbox 失敗重試及稽核。
- Flutter 測試登入／登出與工作台狀態、未查證文案，以及簽章 feed 的新 namespace 接受規則。
- 執行後端測試、Flutter 分析與測試、Android 編譯／測試、部署設定驗證；結果分別列出。
- 手機及真實政府端帳號需由部署環境驗收；本機測試不代表已部署。

## 安全邊界

- 帳號由系統管理者建立；密碼至少 12 字元且不限制字元種類，以 scrypt 雜湊；工作階段只保存 token 雜湊。
- Cookie 僅用於同源 Web，寫入請求要求 CSRF header；Android 使用 Keystore 保護的 token。
- 報告需通過 event-v0、裝置公鑰、payload hash、Ed25519 與期限驗證。上傳回報仍是未查證事件。
- 工作台 API 僅能寫資料庫。發布 worker 才能讀取簽章私鑰和寫入公開 release；簽章表示來源與完整性，不等同事實保證。
