# 政府公告影響範圍與通知接收區域設計

日期：2026-10-21
狀態：已確認

## 目標

讓政府公告依公告類別顯示在合適的通知分類與圖示，並以行政區表達公告影響範圍。發布者可從地圖座標取得行政區建議，再自行調整；使用者可選擇本機通知清單與未讀數要顯示哪些行政區。

這是 Web 與 Flutter／Android 同一批變更。Flutter 共用介面涵蓋 Web 與 Android；公告資料契約、中央發布和 Android 裝置簽章需一起更新。

## 現況與原因

- `NotificationsScreen._categoryFor` 只採用 NCDR／CWA 告警分類，政府公告的 `attributes.category` 沒有參與分組，因此顯示為「一般通知」。
- `MapIconCatalog.forEvent` 目前為物資站提供專用圖示；`SHELTER` 會落到一般災害警示圖示。
- 新增公告表單、伺服器驗證和 Android 裝置公告目前都固定使用 `area_id=tw.national`。地圖座標只作為事件位置，沒有轉成影響行政區。
- 通知清單與未讀數由本機已同步事件建立，個人設定目前沒有行政區接收偏好。
- 政府 Android 工作台可離線建立裝置簽章公告。鄉鎮市區原始邊界檔約 46.7 MB，gzip 約 14.7 MB；不應直接將未加工原始檔打入 Flutter assets。
- Android 與 Web 的政府資料更新已有「全部／臺北」下載範圍。它控制資料同步，與本設計的通知顯示偏好分開。

## 設計決定

### 公告分類與圖示

政府公告在通知分類中依現有 `category` 分成六組，並加上「政府公告」前綴，避免與 NCDR／CWA 同名分類混在一起：安全提醒、天氣、道路、避難收容、物資站、其他。

公告事件圖示由共用 `MapIconCatalog` 依類別決定，地圖標記與通知卡片使用同一映射。避難收容使用既有的 `MapIconCatalog.shelter`；物資站保留既有包裹圖示。其他公告類別也使用對應語意圖示，未分類或未知值使用一般警示圖示。

### 發布者設定影響範圍

新增及修訂公告時，地圖選點會預判所在的最小支援行政區，也就是鄉鎮市區。表單顯示縣市與鄉鎮市區名稱，發布者可在行政區選擇器中加入其他鄉鎮、改選整個縣市，或明確選擇全台灣。縣市選取代表其下轄鄉鎮市區；多個行政區可同時選取。

沒有點位的公告仍須選擇影響範圍。道路、避難收容、物資站維持需要地圖位置的現有規則；點位自動選出行政區後仍可調整範圍。全台灣是明確選項，不是缺少範圍時的預設值。

座標轉行政區使用 `data/boundaries/geojson/county.geojson` 與 `town.geojson` 的縣市／鄉鎮市區邊界。Web 與 Android 共用一份精簡、版本化本機空間索引，保留正式邊界的座標精度與行政區代碼，使離線工作台也能預覽結果；索引以正式來源版本及雜湊識別，伺服器仍以完整行政區目錄驗證發布資料。原始鄉鎮邊界約 46.7 MB，gzip 約 14.7 MB，需在計畫階段量測衍生索引的安裝體積、載入記憶體與查詢時間。若座標不在範圍內或落在多個候選區域而無法唯一判定，表單要求發布者手動確認，不自動改成全台灣。地圖點位與影響範圍分開保存；若發布者調整後點位落在所選範圍之外，表單提示並要求確認。

### 公告事件範圍契約

新增 `attributes.affected_area_ids`，內容為一個或多個正式行政區代碼，例如 `tw.10014020`；全台灣使用 `tw.national`。同時選到縣市及其下轄鄉鎮時，送出前移除被縣市範圍涵蓋的重複鄉鎮 ID。接收者以此欄位判斷影響範圍。公告的 Point geometry 仍代表地圖位置。

為維持現有政府公告來源的全國 feed 分組及舊版事件形狀，`attributes.area_id` 保留為 `tw.national` 的傳輸分組欄位。新版本 UI 不再把這個欄位當作公告影響範圍。對舊公告若沒有 `affected_area_ids`，以既有 `area_id` 解讀；因此舊的 `tw.national` 公告仍視為全台灣。

中央工作台公告與 Android 裝置簽章公告均須寫入 `affected_area_ids`。伺服器驗證所有 ID 都存在於正式行政區目錄；Android 離線建立時，使用同版本的本機索引預先驗證。事件仍使用 event-v0 與現有簽章流程，新欄位須在裝置簽章之前納入 payload。既有客戶端只認得 `area_id`，升級前可能仍將新公告顯示為全台灣；此顯示差異隨客戶端升級消除。

### 通知接收區域

個人設定增加「通知接收區域」，可多選縣市或鄉鎮市區，並能查看及修改目前選取項目。新安裝或尚未設定的使用者預設全台灣，以保留目前通知清單的可見範圍；設定完成後，選取範圍套用在通知列表、分類篩選項目、未讀數與「全部已讀」操作。

偏好保存於目前瀏覽器或裝置的本機儲存，不需要一般使用者帳號。範圍比對依正式行政區階層處理：選縣市會包含其下轄鄉鎮；選鄉鎮會收到該鄉鎮及涵蓋它的縣市級公告；全台灣公告符合所有接收設定。若事件沒有可比對的行政區資料，保留在通知清單中，避免把未知範圍的事件靜默隱藏。

本機區域偏好只篩通知清單與未讀數，不改變地圖事件、資料下載範圍或伺服器傳輸。政府資料更新目前若設定為臺北範圍，其他縣市的警報可能尚未同步；通知設定需提示使用者目前只能篩選已同步到本機的事件。伺服器推播訂閱不在本次範圍。

## 資料與畫面流程

1. 公告發布者在地圖選點；Flutter 使用精簡行政區索引顯示推定鄉鎮市區。
2. 發布者確認或修改行政區範圍，表單保留獨立的地圖座標與影響區域清單。
3. Web 將範圍送至政府工作台 API；Android 將範圍納入裝置簽章事件。伺服器驗證行政區 ID 後儲存並透過既有中央簽章 feed 發布。
4. Web／Android 取得並驗證公告事件後，App controller 依本機接收區域產生通知列表與未讀數；地圖仍使用完整已同步事件。

## 錯誤處理與相容性

- 座標無法判定或有多個候選行政區：要求手動選擇或確認候選，不發布未指定範圍的公告。
- 未提供影響區域：阻止發布；只有明確選取 `tw.national` 才能發布全台公告。
- 本機接收偏好缺失或無法讀取：套用全台灣預設並保留可見通知。
- 舊公告缺少 `affected_area_ids`：使用舊 `area_id`；`tw.national` 仍視為全台。
- 舊客戶端無法讀取新影響區域欄位；新 Web 與 Android 版本需在同一發布批次更新，避免同版平台呈現不一致。

## 驗收條件

- 六種政府公告各自出現在對應分類；政府公告分類與同名氣象／災害分類可辨識地分開。
- 避難收容公告在地圖和通知卡片都使用避難收容圖示；物資站仍使用物資站圖示。
- 相同座標在 Web 與 Android 離線工作台解析為相同行政區；發布者可確認、擴大、縮小或多選影響區域。
- 發布事件的簽章涵蓋 `affected_area_ids`；伺服器拒絕未知行政區 ID。
- 接收區域可選縣市、鄉鎮或全台；通知清單、未讀數、分類篩選與全部已讀結果一致。
- 改變通知接收區域不會移除地圖事件，也不會改寫政府資料更新下載範圍。
- 舊版全台公告與未指定區域的既有事件維持可見。

## 不包含的功能

- 以公里數設定圓形半徑或繪製自訂多邊形。
- 伺服器端使用者訂閱、Web Push 或手機推播。
- 依接收偏好裁切地圖事件或變更 Mesh／feed 傳輸路由。
- 村里層級的公告範圍選擇。
